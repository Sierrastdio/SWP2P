# SWP2P 통신 버스 프로토콜 설계 스펙

## 프로젝트 목적
SPI/I2C/CAN처럼 "슬레이브-마스터-슬레이브"를 거쳐야 하는 오버헤드 없이, 노드 간 **직접 통신**이 가능하면서도 하드웨어 UART 시리얼통신보다 빠른 경량 버스 프로토콜을 Verilog(SystemVerilog)로 설계하고, 최종적으로 아두이노(AVR) 라이브러리로 이식한다.

## 설계 철학 (핵심 원칙)
1. **가변 데이터선(WIDTH)**: 라이브러리 사용자가 코드 작성 단계에서 데이터선 개수를 1~8 사이로 설정할 수 있어야 한다. 핀 수와 속도의 트레이드오프를 사용자가 직접 선택.
2. **완전한 마스터리스 구조**: CLK은 노드 중 하나가 출력하거나 외부 클럭을 사용할 수 있지만, 클럭을 출력하는 노드가 "마스터" 역할(중재자, 조정자)을 갖지 않는다. 모든 노드는 대등(peer-to-peer)하다.
3. **최소 라인 구성**: BUSY_N, ACK_N, DATA_BUS(WIDTH비트) 만으로 구성. 아두이노 10개 노드를 매달아도 문제없이 동작해야 한다.
4. **저지연**: 통신 사이클(프레임) 하나가 하드웨어 시리얼(UART)보다 확실히 빨라야 한다. 목표는 최소 5~10배.
5. **전기적 특성**: BUSY_N, ACK_N, DATA_BUS 전 라인 open-drain(wired-AND) + 외부 pull-up. 노드 수 증가에 따른 버스 커패시턴스 상승을 감안해 pull-up 저항값은 실물 단계에서 재조정 예정.

## 참고 모델과의 관계
- 개념적으로 **CAN 버스의 비트단위 우선순위 중재(wired-AND arbitration)** 를 차용한다. "마스터 없는 대등 통신"이라는 아이디어 자체는 CAN과 동일 계열이며, 이 프로토콜이 CAN보다 가벼운 이유는 CAN의 11~29비트 ID, CRC, 여러 필드 등 무거운 프레임 구조를 걷어내고 8비트 주소 + 최소 필드로 극단적으로 경량화했기 때문이다.
- I2C/SPI와 달리 브로드캐스트 및 슬레이브 간 임의 통신이 프로토콜 레벨에서 기본 지원되어야 한다.

## 라인 정의
| 라인 | 방향 | 특성 |
|---|---|---|---|
| CLK | D2(intput) / D9(output) | 노드 중 하나 출력 또는 외부 입력 | 공유 클럭, 중재자 역할 없음 |
| BUSY_N | D3 | 양방향, open-drain | 버스 점유(프레임 진행 중) 표시. Idle=1(release), 점유 중=0 |
| ACK_N | D8(추후 변경가능하게 수정예정) | 양방향, open-drain | 수신 확인. 정확히 1클럭 폭의 LOW 펄스 |
| DATA_BUS[WIDTH-1:0] | 남는선 | 양방향, open-drain, WIDTH=1~8 (사용자 설정) | 주소/데이터 운반 |

## 프레임 구조
```
[Idle 감지: BUSY_N==1]
  → [중재(Arbitration) 단계: ceil(8/WIDTH) 클럭]
      · 송신 예정 노드들이 자신의 NODE_ID를 MSB부터 WIDTH비트씩 동시에 구동
      · open-drain 특성상 0을 미는 노드가 항상 우선(dominant bit)
      · 자신이 1(release)로 보낸 비트인데 버스 값이 0으로 읽히면 즉시 패배 → busy_out<=1, 송신 포기(재시도는 다음 idle에)
      · 마지막 청크까지 살아남은 노드가 유일한 송신자로 확정
  → [데이터 단계: ceil(8/WIDTH) 클럭]
      · 확정된 송신자가 실제 데이터 바이트를 WIDTH비트씩 구동
  → [Release: 1클럭] (data_out을 idle값으로 복귀)
  → [ACK 단계: 1클럭]
      · 수신자(주소가 일치하는 노드, 혹은 브로드캐스트 시 전체)가 ACK_N을 정확히 1클럭만 LOW로 구동
  → [Idle 복귀: BUSY_N<=1]
```

## 핵심 로직 요구사항
1. **WIDTH 파라미터화**: `ARB_CYCLES = ceil(8/WIDTH)`를 자동 계산. WIDTH=8이면 중재 1클럭(완전 병렬), WIDTH=1이면 8클럭(완전 직렬)로 자연스럽게 양극단을 커버해야 한다.
2. **0xFF sentinel 문제 해결**: 데이터 유효성 판단에 `data_bus != 0xFF` 같은 매직값 비교를 쓰지 않는다. 대신 "이 프레임에서 아직 캡처하지 않음" 상태 플래그(`captured_this_frame`)로 유효성을 판단해, 실제 페이로드가 0xFF/0x00 등 임의값이어도 정상 전송되어야 한다.
3. **이중 캡처 방지**: BUSY_N이 재차 풀릴 때까지 동일 프레임에서 같은 바이트를 두 번 FIFO에 넣지 않도록 프레임 단위 캡처 플래그로 원천 차단한다.
4. **NODE_ID 기반 주소 지정**: 프레임 첫 필드(중재에 사용된 값 자체)가 목적지 주소 역할을 겸한다. 수신 노드는 자신의 NODE_ID와 일치하거나 브로드캐스트 값(예: 8'hFF)일 때만 데이터를 FIFO에 저장하고 ACK를 건다.
5. **동시 송신 충돌 방지**: 중재 단계에서 패배한 노드는 즉시 버스를 양보(`busy_out<=1`)하고, 승리한 노드만 데이터 단계로 진입한다. 데이터 페이즈에서는 유일한 구동자만 남아있으므로 버스 컨텐션이 구조적으로 발생하지 않는다.
6. **NODE_ID 유일성**: 마스터가 없어 런타임 검증 수단이 없으므로, 컴파일 타임(파라미터)에서 사용자가 직접 유일한 ID를 부여하도록 강제. (선택 확장: 부팅 시 중재를 이용한 자동 ID 할당)
7. **Rx FIFO**: 노드당 최소 depth 4의 하드웨어 FIFO로 수신 데이터를 버퍼링, CPU(또는 상위 로직)가 비동기로 읽어간다.

## 성능 목표 (검증 기준)
- 기준 비교 대상: 아두이노 하드웨어 UART, 115200bps(바이트당 ≈86.8us) 및 1Mbps(≈10us)
- 아두이노 구현 시 `digitalWrite()` 대신 **포트 레지스터 직접 제어(PORTB/PORTD 등)** 사용을 전제로 설계
- WIDTH=1 구성만으로도 UART 115200bps 대비 약 10배 이상 빠른 프레임 전송시간을 목표로 한다 (중재+데이터+release+ack 합산 약 18클럭 내외)
- WIDTH≥4 구성에서는 UART 1Mbps보다도 빠른 것을 목표로 한다


## 아두이노(AVR) 이식 시 CPU 부담 최소화 원칙 (필수)
통신 중 CPU 개입을 최소화하기 위해 AVR 내장 하드웨어 유닛을 최대한 활용한다. 소프트웨어 폴링/비트뱅잉은 최후 수단으로만 쓴다.

1. **CLK 생성 — Timer/Counter CTC 모드 + OC 핀 하드웨어 자동 토글**
   - CLK을 출력하는 노드는 `delay()`나 소프트웨어 루프로 토글하지 않는다.
   - Timer(Timer0/Timer1)를 CTC 모드로 설정해 `OC0A`/`OC1A` 등 Output Compare 핀이 하드웨어적으로 자동 토글되도록 한다.
   - CPU는 초기 레지스터 설정 1회만 수행하고 이후 클럭 생성에 전혀 개입하지 않는다. 소프트웨어 토글 대비 지터도 낮아 타이밍 마진 축소 여지가 생긴다.

2. **BUSY_N/ACK_N 엣지 감지 — External Interrupt(INT0/INT1) 우선 사용**
   - PCINT(포트 단위 Pin Change Interrupt)는 ISR 진입 후 어떤 핀이 바뀌었는지 소프트웨어로 재판별해야 하는 오버헤드가 있으므로 지양한다.
   - 대신 **INT0/INT1처럼 핀 전용 + 엣지 방향(상승/하강) 하드웨어 지정이 가능한 외부 인터럽트**를 사용한다.
   - 라이브러리 스펙 상 BUSY_N, ACK_N은 각각 INT0, INT1에 대응하는 고정 핀(예: Uno 기준 D2, D3)에 배치하는 것을 표준으로 못박는다.

3. **정밀 타이밍이 필요한 이벤트 — Input Capture Unit(ICU, Timer1) 활용**
   - 중재(arbitration) 단계에서 패배 시점 판별, ACK 타이밍 검증 등 정확한 엣지 시각이 필요한 경우 ICU를 사용한다.
   - CPU가 타이머를 지속적으로 폴링하지 않아도, 엣지 발생 시각이 자동으로 캡처 레지스터에 래치되고 인터럽트가 발생하므로 ISR에서 값만 읽으면 된다.

4. **제외 대상: 하드웨어 SPI 시프트레지스터**
   - WIDTH비트 병렬 데이터를 SPI 하드웨어로 밀어내는 방안은 검토했으나, SPI 자체 클럭선(SCK)과 공유 CLK 간 동기화 복잡도, AVR에 DMA가 없어 얻는 이득이 적다는 점 때문에 이번 단계에서는 채택하지 않는다.

5. **Rx FIFO는 ISR 내에서 최소 작업만 수행**
   - ISR은 데이터 캡처와 FIFO push만 수행하고, 상위 애플리케이션 로직(CPU 메인 루프)에서 비동기로 FIFO를 소비하도록 분리한다. ISR 체류시간이 곧 다음 클럭 사이클 타이밍 여유를 잠식하므로 최소화가 최우선.
